SYSTEM OVERVIEW & ZERO-BUDGET STRATEGY
================================================================================
Target Platform: Real-time team collaboration system featuring:
• User ID / Tag-based member invitation and removal (RBAC: Admin / Member).
• Channels & direct personal messaging (1-on-1 DMs).
• Project workspaces with subtasks, priority levels, and deadlines.
• Performance analytics dashboards (Team completion rate, member workloads).

Zero-Cost Infrastructure Stack:
• Database: MongoDB Atlas (M0 Free Tier - 512MB storage).
• Backend API & Sockets: Node.js / Express hosted on Render/Railway/Fly.io (Free Tier).
• Frontend: React + Tailwind CSS hosted on Vercel / Netlify (Free Tier).
• Real-Time Transport: Native Socket.io (zero third-party paid services like Pusher/Ably).

3. COMPLETE DATABASE DATA MODELS (MONGOOSE SCHEMAS)

User Model (User.js)
• _id: ObjectId
• name: String (Required)
• email: String (Unique, Required)
• username: String (Unique handle/ID for direct invites, e.g., "alex_dev" or "user_102")
• password: String (Hashed with bcrypt in pre-save hook)
• avatarColor: String (Hex code for fallback avatar)
• createdAt: Date

Team Model (Team.js)
• _id: ObjectId
• name: String (Required)
• description: String
• admin: ObjectId (Ref: User)
• members: [
{
user: ObjectId (Ref: User),
role: String (Enum: ['Admin', 'Member'], Default: 'Member'),
joinedAt: Date
}
]
• createdAt: Date

Project & Subtask Model (Project.js)
• _id: ObjectId
• teamId: ObjectId (Ref: Team, Indexed)
• title: String (Required)
• description: String
• createdBy: ObjectId (Ref: User)
• deadline: Date
• subtasks: [
{
_id: ObjectId,
title: String (Required),
assignedTo: ObjectId (Ref: User, Nullable),
priority: String (Enum: ['Low', 'Medium', 'High', 'Urgent'], Default: 'Medium'),
status: String (Enum: ['To Do', 'In Progress', 'Completed'], Default: 'To Do'),
deadline: Date,
completedAt: Date
}
]
• createdAt: Date

Message Model (Message.js)
• _id: ObjectId
• teamId: ObjectId (Ref: Team, Indexed)
• sender: ObjectId (Ref: User, Required)
• recipient: ObjectId (Ref: User, Null if public channel message)
• content: String (Required)
• createdAt: Date (Indexed for chronological streaming)

4. TOPIC-BY-TOPIC BACKEND ROADMAP & CONCEPTUAL GUIDE

STAGE 1: Server Setup & Configuration

• Topic 1.1: Express Setup & Environment Isolation

Core Modules: express, dotenv, cors.

Role: Encapsulates database connection strings and JWT secrets within .env
to prevent credentials exposure in Git repositories.

• Topic 1.2: MongoDB Connection Resilience

Core Module: config/db.js.

Role: Establishes a persistent Mongoose connection with lifecycle event
listeners (connected, error, disconnected).

STAGE 2: Express Middlewares Pipeline

Middlewares execute sequentially in the request-response cycle before the
controller executes.

• Topic 2.1: Authentication Middleware (auth.middleware.js)

Operation: Intercepts the "Authorization: Bearer " header, decodes
the token with jwt.verify(), queries user data, and binds it to req.user.

Benefit: Eliminates repetitive authentication logic across secure routes.

• Topic 2.2: RBAC & Team Membership Middleware (rbac.middleware.js)

Operation: Inspects req.params.teamId to verify that req.user._id matches
the admin ID or an authorized member role for that specific team.

Benefit: Enforces boundary controls so regular members cannot remove
colleagues or delete projects.

• Topic 2.3: Centralized Error Handler (error.middleware.js)

Operation: A 4-parameter function (err, req, res, next) placed as the final
Express layer.

Benefit: Catches unhandled async promise rejections and standardizes API
error payloads:
{ "success": false, "message": "...", "error": "..." }

STAGE 3: Database Models & Lifecycle Hooks

• Topic 3.1: Password Hashing Hooks (bcrypt)

Pre-save hook automatically triggers when user.password is modified,
ensuring unhashed plain-text passwords never reach storage.

• Topic 3.2: Embedding vs. Referencing

Projects embed Subtasks for atomic updates and fast read operations.

Users and Teams use References (ObjectId) to prevent document bloat and
maintain data normalization.

STAGE 4: Controllers & API Endpoints

• Topic 4.1: Authentication Endpoints

POST /api/auth/register : Registers account, verifies unique username/ID.

POST /api/auth/login    : Authenticates credentials, returns signed JWT.

GET  /api/auth/me       : Returns current authenticated session details.

• Topic 4.2: Team & User ID Member Management Endpoints

POST   /api/teams                        : Creates workspace with creator as Admin.

POST   /api/teams/:teamId/members        : Queries User.findOne({ username }) and adds to team.

DELETE /api/teams/:teamId/members/:userId : Removes user from team and clears task assignments.

• Topic 4.3: Project & Subtask Workflows

POST  /api/teams/:teamId/projects           : Instantiates a project container.

POST  /api/projects/:projectId/subtasks     : Inserts subtask into project array.

PATCH /api/projects/:projectId/subtasks/:id : Modifies status and logs completedAt.

STAGE 5: Native Real-Time WebSockets (Socket.io)

• Topic 5.1: Socket Handshake Authentication

Middleware inside io.use() validates the JWT token before allowing
the client connection.

• Topic 5.2: Room Isolation & Events

socket.join(teamId) : Broadcasts team announcements, project updates, and group chat.

socket.join(userId) : Routes personal 1-on-1 private direct messages.

Formula: (Total Completed Subtasks / Total Subtasks) * 100
